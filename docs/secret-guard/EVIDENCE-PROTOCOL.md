# Protocole de preuve Developer Guard

Pour chaque contrôle annoncé comme bloquant, conserver trois observations réalisées avec des données synthétiques : l’action interdite est refusée sans effet, l’action légitime passe, et le même essai atteint le récepteur de laboratoire une fois le garde retiré. Les journaux ne contiennent ni prompt, ni secret, ni argument d’outil, ni chemin utilisateur.

Une preuve indique l’hôte, sa version, l’OS, l’événement, la version de politique, le scénario, le commit et la date. Une preuve d’un outil MCP ne prouve pas une interception VS Code. Une preuve de configuration n’est pas une preuve d’invocation.

Les échecs de runner, signature invalide, expiration et capacité inconnue sont enregistrés comme états non vérifiés ou refusés ; ils ne rendent pas le poste vert.
